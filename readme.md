# IoT Device Telemetry Medallion Pipeline on Databricks DLT

An enterprise-grade, batch-oriented data pipeline built using **Databricks Delta Live Tables (DLT)** and **Medallion Architecture**. This pipeline ingests complex nested JSON logs from smart devices via Unity Catalog Volumes, handles schema drift gracefully, tracks data lineage, filters late arrivals, and generates rich analytical Gold tables.

---

## 🧰 Tools and Technology

* **Databricks Runtime & Delta Live Tables (DLT):** Declarative framework for building reliable, automated data pipelines with built-in orchestration and quality checks.
* **PySpark & Delta Lake:** Distributed data processing engine and open-source storage layer providing ACID transactions, time travel, and high-performance querying.
* **Databricks Unity Catalog Volumes:** Secure governance and storage mount point for raw incoming IoT JSON files (`/Volumes/...`).
* **Auto Loader (`cloudFiles`):** Incremental file ingestion engine with RocksDB state tracking and RocksDB schema rescue mode (`schemaEvolutionMode='rescue'`).
* **Uber H3 Spatial Indexing:** Native Databricks geospatial functions (`h3_pointtocell`) for grid-based regional density aggregation.

---

## 📊 About the Data & Expected Outputs

### 1. About the Data
The input data consists of raw, batch-dropped JSON files generated by IoT smart devices (such as smartwatches). Key characteristics include:
* **Nested & Variable Structures:** Contains nested `location` structs (`lat`, `lon`, `accuracy_m`) and a variable-length `sensor_readings` array.
* **Schema Drift:** Different device firmware versions introduce new attributes or alter data types (e.g., `battery_pct` as string vs. integer).
* **Irregular Batch Syncs:** Devices cache data offline and batch-sync intermittently every 5 to 30 minutes, resulting in overlapping time ranges and late-arriving records.
* **Optional Metadata:** Dynamic or empty `error_codes` arrays requiring lookup enrichment.

### 2. Expected Outputs
* **Resilient Raw Storage:** Immutable historical logs capturing every drop with zero data loss, even when unexpected schema changes occur.
* **Cleaned & Flattened Analytical Tables:** Standardized, de-duplicated rows with exploded sensor arrays and normalized data types ready for BI tools.
* **Predictive & Operational Insights:** Actionable Gold-layer metrics tracking device health anomalies, network sync gaps (churn/failure signals), and regional spatial density heatmaps.

## 🏗️ Pipeline Architecture & Layer Breakdown


```

[ Unity Catalog Volume ]
│ (Auto Loader / Batch Trigger)
▼
🥉 BRONZE LAYER (Raw Ingestion & Schema Protection)
│
▼
🥈 SILVER LAYER (Flattening, Deduplication, & Enrichment)
│
├──────────────────────────────┬──────────────────────────────┐
▼                              ▼                              ▼
🥇 GOLD: Health & Anomalies    🥇 GOLD: Uptime Gaps           🥇 GOLD: Geo-Density (H3)

```

### 🥉 Bronze Layer: Raw Ingestion & Traceability
The Bronze layer acts as the immutable landing zone. 
* **Auto Loader Integration:** Uses `spark.readStream.format("cloudFiles")` in a scheduled batch trigger mode to incrementally process new JSON drops from Unity Catalog Volumes without scanning historical files.
* **Schema Evolution & Rescue:** Configured with `schemaEvolutionMode='rescue'` and `rescuedDataColumn='_rescued_data'`. Unexpected attributes or type conflicts are safely isolated rather than crashing the pipeline.
* **Lineage Tracking:** Injects metadata columns (`_ingested_at`, `_source_file`, `_file_modification_time`, and `_batch_id`) to maintain complete end-to-end auditing.

### 🥈 Silver Layer: Transformation, Flattening, & Cleaning
The Silver layer processes the raw Bronze tables into clean, structured, and validated domain models:
* **Array Explosion & Struct Flattening:** Uses `explode_outer` to expand the `sensor_readings` array into individual rows while preserving parent records, and flattens `location` struct coordinates.
* **Deduplication:** Removes redundant sync retries based on compound keys (`device_id`, `sensor_type`, `reading_ts`).
* **Late Arrival Handling:** Identifies and tags records where `event_timestamp` lags significantly behind ingestion time for downstream monitoring.
* **Error Code Enrichment:** Performs a broadcast join against a curated Delta reference table (`error_lookup_dim`) to translate error codes (e.g., `E001`) into human-readable descriptions and severities.
* **Data Quality Filters:** Enforces constraints (e.g., battery percentage between 0 and 100, valid heart rate ranges).

### 🥇 Gold Layer: Analytical Datamarts
The Gold layer provides aggregated, business-ready tables optimized for reporting and machine learning models:
* **Device Health Fact Table:** Computes battery drain trends and error frequency per device/day.
* **Sensor Anomaly Table:** Isolates statistical outliers and sensor glitches (e.g., abnormal heart rate spikes).
* **Uptime & Connectivity Table:** Analyzes time gaps between sync events per device using Window functions (`lag()`) to serve as a churn or hardware failure prediction signal.
* **Geo-Distribution Table:** Bins precise coordinates into regional grid cells using native H3 spatial indexing (`h3_pointtocell`) for spatial heatmaps.
